The heart of our system  is driven by an LLM that can call tools, but all incoming content from the user first goes through a prequalifier (PQ), performing basic security (e.g., rate limiting and sanitization), searching for vagueness, and detecting frustration/hostility by the user. The PQ uses these diagnoses to modify the prompt to the LLM (e.g., modifying the user's input in the case of sanitization and giving instructions for dealing with the vagueness and/or hostility (from acknowledge the frustration to offer to chat with a human).
After the LLM does all its tool calls and is satisfied with an answer, that answer goes through an Output Validator (OV). It checks for things like conformity to FEC rules, conformity to campaign legal mandates, that the answer actually answers the intent of the user's question, that the answer does not further inflame a volatile situation, that all PII is redacted, and verifies all citations. If there is a violation, the OV rejects the answer and sends it back to the LLM with an explanation of why it was rejected.

Unfortunately, this exercise brought out a missing component – verifying web retrievals. For that, let’s do this:
```
When the main LLM cites a web page, you need a reliable way to prove that the statement actually appears on that page and that the page is a legitimate source. Here’s a practical pipeline:
Anchor injection at ingestion
Add storage to perform_web_search. When you retrieve a web article, scrape the HTML, strip formatting, and insert a unique anchor at the start of each factual sentence.
Example:
Text
The candidate supports a $2 trillion infrastructure plan [WEB-2023-09-12-ARTICLE-045].
Store the anchor together with the URL, the exact sentence, and a short hash of the sentence content in a citation metadata table.
LLM citation requirement
In the prompt to the main LLM, include a strict instruction when using perform_web_search():
```
Whenever you state a factual claim, append a citation anchor from the provided context,
e.g. [WEB-2023-09-12-ARTICLE-045]. Do not generate any claim without a valid anchor.
```
Verification step in the Output Validator (OV)
a. Extract anchors – run a regex (\[WEB-[^\]]+\]) on the LLM output.
b. Lookup – for each anchor, query the citation metadata table. Verify that the anchor exists and that the sentence the LLM produced matches the stored sentence (hash comparison).
c. Web‑freshness check – because web pages can change, fetch the live page (via a headless browser) and re‑extract the sentence. If the live content differs by more than a small tolerance (e.g., Levenshtein distance > 5 %), treat the citation as unverified.
If any anchor fails lookup or freshness, the OV sets status = WARNING (or BLOCKED for high‑severity) and returns a message like:
```
The statement “…” could not be verified against the source [WEB-2023-09-12-ARTICLE-045].
Please ask for clarification or provide a different source.
```
